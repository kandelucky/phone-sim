Phone simulator: user guide

A phone on your computer screen, for trying out an app before it becomes a real Android app. No installation, no internet needed.

The simulator speaks other languages too: ⚙ → Language (on first start it follows your browser's language). The Info button (ⓘ) shows this same guide inside the simulator, in that language. For people who only test an app: the short version.

1. Open it

Double-click sim.html. It opens in your browser (Chrome or Edge work best). You see a phone with the app inside it and the console, a list of what the app is doing (see Console panel below). Hold the mouse over any button to see its name and a short hint.

2. Buttons

The top bar has three parts: on the left Open app and Reload, sound, touch and capture; in the middle, right above the phone, Back, Background and Close, and Table beside them; on the right Two phones, Rotate and Device, Zoom, the console panel, ⓘ and ⚙. The buttons do what a real phone does; hold the mouse over one for a short hint.

Open app The first button of the bar: which app opens in the phone. It opens a small panel; click outside it or press Esc to close it. Choose folder… = pick the app's folder (index.html, or www/ or dist/) and the app opens from it; sim-bridge.js is added by itself, ↻ shows your edits, a page refresh forgets the folder. Choose APK… = an Android app file (.apk): its web part opens (assets/public/: Capacitor, assets/www/: Cordova, Construct 2); a native app (Java / Kotlin, Unity, Flutter) does not, and the console says so. Both buttons work only when the simulator is opened as a web page (the live demo or a local server), in Chrome or Edge. The field under it: a path from sim.html (e.g. myapp/index.html), a file path from Windows (Shift + right-click the file → Copy as path) or an address (e.g. http://localhost:5173), then Enter. Empty = the default app, or an empty phone if there is none. It goes into the address bar, so a refresh opens it again. A file path works only while the simulator itself is opened from a file. An app opened from the field needs sim-bridge.js, or it only shows in the frame. Under the field: Try it now = the demo app and a few websites, opened at once. Google, YouTube, GitHub and most big sites do not open: see Limits → Other websites. Download the demo app (zip): unzip it, then choose its folder.
Back The phone's back button; ◁ on the phone (3-button mode) and a swipe in from the edge (Gestures mode) do the same. What it means is up to the app: the previous screen, closing a window, or nothing. It does not reach an app that is in the background or closed.
Background As if you pressed Home or switched to another app. The app is told it is hidden, and its animations stop. A cover sits over the screen. ○ on the phone (3-button mode) does the same.
Return Brings the app back from the background. It should continue where it was.
Close / Open As if the app was swiped away from the recent-apps list, or the phone closed it to free memory. The app gets no warning: anything it had not saved is lost. The next press (Open) starts the app from scratch; only saved data survives.
Table Right of Close, in its own group. The phone lies on a table: drag the ✥ handle (or the phone's frame) to move it, the ↻ handle to turn it; it snaps at 0° / 90° / 180° / 270°. Turned to the right exists only here; upside down too, but on a tablet only: an Android phone does not turn its screen upside down, it stays as it was. A small bar beside the phone: Upright, Sideways (both straight) and Centre (back to the middle). The place and the turn are remembered, even after a reload. Press again = the tools close, the phone stays where it is. A tilted phone (not at a right angle) greys Screen and Phone in Screenshot and Video; Whole window still works. The same switch is in the presentation card.
Rotate Upright ↔ sideways. On the icon the faint screen = now, the solid one = after the press. The simulator remembers it.
Mute All the app's sound goes quiet at once; the button stays filled while the sound is off. The waves on the icon = the current level. Level: ⚙ → Volume.
Finger / mouse Over the screen the mouse is a finger or a plain mouse. More: the “Finger and zoom” tab.
Screenshot The button opens a menu; each choice downloads a PNG file. Screen: the phone's screen only (with the system bars, without the camera and the rounded corners). The console writes the size and whether it fits Google Play's rule: each side 320–3840 px, the long side at most twice the short one. 360 × 800 is too long; ⚙ → Size 360 × 640 fits. Phone: the phone with its frame and camera, on a transparent background, no shadow. For about a second the background turns black, then white: the two frames give the file its transparency. Whole window: the simulator as you see it. The browser asks for permission every time: pick this tab. For the shot Chrome draws the tab twice as sharp, so the file is twice the size the phone shows at on your monitor; for more, raise the zoom (for Screen and Phone the whole phone must be in view). In Table mode () Screen and Phone need the phone at a right angle (0° / 90° / 180° / 270°): a tilted phone greys them, Whole window still works. Works in Chrome and Edge.
Video The phone as a video file. Press = a menu; a pick = recording starts: the browser asks for permission, pick this tab. While it records, the button is red and the time shows beside it. Press again = it stops and the file downloads; the browser's own “Stop sharing” stops and saves it too. Screen: the screen only (with the system bars and the touch circles, without the camera and the rounded corners). Phone: the phone with its frame and camera, no shadow, on the page's background (an MP4 cannot be transparent), touch circles included. While it records, Rotate, Device and Size are locked, Zoom is not. Both work in presentation mode too. In Table mode () only with the phone at a right angle: a tilted phone greys them. Format: MP4 if the browser can write it, otherwise WEBM. Sound: ⚙ → Sound in video. The console writes the size, length, format and MB.
Presentation mode The top bar, the console and the ⓘ beside the phone hide; only the phone stays, in the middle of the window. It works as usual. A faint dot sits in the window's top-left corner: the mouse on it opens a card with four buttons: Video and Screenshot (the same menus as in the top bar), Table (the same switch as in the top bar) and Exit; 0.8 s after the mouse leaves, it folds back into the dot. On entering, the card shows for a few seconds. While a video records, the dot blinks red and the time shows beside it. The dot and the card do not show in a screenshot or a video. With Table on, its tools stay here too (on the left: under the card); a Screen or Phone picture or video leaves them out. Esc exits too when the app does not have the focus (click outside the phone first). The zoom stays as it was. Not remembered: a refresh opens the normal view. Leaving it while a video started here records stops the recording and saves the file.
Reload Right of Open app, in its group. Starts the app again. The console keeps its lines, so you can compare before and after.
Two phones Left of Rotate. A second phone in a floating window over the first, same app. Drag its head to move it, any corner to size it, ✕ closes it; place and size are remembered. Inside it: its own Mute, Finger mode, Rotate, device list and Zoom. Open app and Reload reach both; Back, Background and Close stay with the first phone. Screenshot → Whole window shows both. Its lines come to the console marked ②.
Device Left of Zoom. Which phone or tablet, grouped by maker: Samsung (foldables too, folded / open), Pixel, iPhone, iPad and generic sizes (an old small Android, a tall screen, a small tablet); newest first in each group. The first start shows Pixel 6 Pro, later the one you picked last. A real device shows in its own frame: body, keys, the hole or notch where it is. An iPhone or the iPad turns on iPhone mode: iOS bars and safe areas, a home line instead of ◁ ○ □, no system Back (Bars and Camera in ⚙ are off). The numbers (e.g. 360×800) are the size the app “sees”, not the screen's hardware pixels. Not in the list? Your own size: ⚙ → Size.
100% Zoom How big the phone is on your monitor. The button shows the current scale; a click opens its panel: a slider 40-200%, Fit · 50% · 100% · Natural. More: the “Finger and zoom” tab.
Console panel Where the console sits: Auto (the start: right of the phone, or under it when the window is taller than wide, e.g. an upright monitor), Right (upright, beside the phone), Bottom (wide, under the phone) or Hidden. The icon shows where it is now; a click opens the menu. Size: drag the panel's inner edge (width 260–900 px and at most 60 % of the window, height from 120 px to 60 %). A double click on the edge, or Default size in the menu = 400 / 260 px. The simulator remembers it. In a narrow window (under 800 px: a phone, a tablet held upright) the console is a strip at the bottom: the arrow or a tab opens it to half the window, the arrow closes it.
Info This window. Close it with ✕, Esc or a click outside.
Settings Opens the ⚙ panel. More: the “Settings” tab.

3. Finger and zoom

Finger mode is on from the start. Over the phone screen the mouse becomes a finger and the app gets real touches. Outside the screen the mouse stays a normal mouse.

Press A small white circle appears where the finger touches. Instead of the arrow, a faint ring shows where the finger will land.
Drag The pressed finger slides; a list or a page scrolls under it. A move of more than ~10 px no longer counts as a tap.
Wheel = two fingers Two circles, one on each side of the cursor. Wheel up = they move apart (zoom in), wheel down = they come together (zoom out). They lift a moment after the wheel stops.
Mouse mode Press the finger button. The mouse is a plain mouse on the screen too, for what a fake finger cannot do: a drop-down list, a slider, selecting text.
100% Zoom A button in the top bar; a click opens its panel. Fit = the phone fits the window, at most 100%. The slider = 40 to 200%, in steps of 10; 50% and 100% have buttons too. Natural = real size: the phone on the screen is as big as in your hand (a real device by its body's millimetres; a generic size or your own = Android's 160 dp per inch); the button then shows 1:1. For this the simulator must know the screen's density: the panel's bottom line → Calibrate: hold a bank card to the screen and match the outline (no card: a ruler, the outline = 85.6 × 54 mm). It is saved for each screen; on an unknown screen Natural opens Calibrate first. Windows scaling and the browser's Ctrl +/− do not spoil the size. When the phone does not fit, scroll with the scrollbars or with the wheel outside the screen. Nothing changes for the app.
Right click Opens the browser's menu (Inspect); the app does not see it.

4. Settings

⚙ opens the panel. Click outside it or press Esc to close it. Every choice is remembered.

Size Type your own width × height if your phone is not in the Device list in the top bar.
Bars The phone's top bar (clock, battery) and bottom bar. Gestures = a thin line at the bottom, as on new phones; in finger mode: a swipe in from the left or right edge = Back (an arrow shows at the edge; a short swipe does nothing), a swipe up from the bottom line = Home. The app no longer gets such a touch (touchcancel), as on a phone. 3 buttons = ◁ ○ □: ◁ = Back, ○ = Home (the app goes to the background), □ does nothing; on a sideways phone (not a tablet) they move to the right edge. Hidden = a full-screen game, no bars. Default: 3 buttons.
Camera hole The front camera's hole in the screen, on by default. Upright it is at the top, sideways on the left. It covers a strip of the screen even when the bars are hidden.
Theme Colour sets (light, dark and more) for apps that use themes. The app changes its colours at once.
Volume The phone's volume buttons: 0 to 15, as on Android. Changes all the app's sound (music, effects) at once; the phone shows its volume bar for a moment. The app is not told, as on a real phone. Moving the slider turns mute off.
Ads Ads come = the app gets a test ad. No ads = every load fails with “No fill”, as offline or when there is nothing to show. This is how you check that the app works without ads too. It acts only on an app that uses AdMob (the “For app builders” tab).
Touches in console On by default. In finger mode every gesture becomes one console line: tap x, y · double tap · swipe (arrow = the way the finger moved, distance, time) · scroll (the browser scrolled by itself) · two fingers: apart / together × · gesture from the edge / the bottom (Gestures mode). At the end = the element the finger landed on. In the filter: “Touches”.
Internet Off = as if the phone had no internet. The app's own files still load (in an APK they are on the phone), but a request to another address (fetch, XMLHttpRequest) fails, navigator.onLine is false, the app gets the offline / online event, and no ads come. The signal and Wi-Fi icons in the status bar fade. Pictures and scripts loaded by an HTML tag are not stopped.
Font size Android's “Font size” setting. On a phone the WebView makes text bigger with it while the boxes stay the same, so text may no longer fit. 130% and 200% show where the layout breaks. Text drawn on a canvas does not change. An estimate: a line height given in px does not grow.
FPS meter A number in the corner of the screen: how many frames a second the app draws, and the longest frame of the last half second (ms). Green = 55+, yellow = 30+, red = fewer. A PC is faster than a phone: what stutters here is worse on a phone; what is smooth here still needs a check on a phone.
Sound in video On by default. A video records the app's sound too (music, effects), at the ⚙ → Volume level. In the browser's question, sharing the tab's sound must be on; if it is not, the video records without sound and the console says so.
Language The last row of the panel. The simulator's own words: English, Georgian, or any language that has a file in lang/. One choice for all projects. The app inside the phone does not change.

5. Screen and console

The faint ⓘ beside the phone's bottom right corner: click or tap it, and a line tells you what the app gets right now. For example:
Galaxy A15, typical · 360 × 800 · app 360 × 800 · under the bars: ↑28 ↓22 ←0 →0 · 75%

360 × 800 The screen size.
app 360 × 800 The space the app draws on.
under the bars ↑ ↓ ← → How much of each edge (top, bottom, left, right) a bar or the camera hole covers. Buttons and text must keep out of these strips. If this part is missing, the bars never cover the app; its space is simply smaller.
100% 75% How big the phone is shown: Fit, the zoom you picked or Natural. It does not affect the app.
Console The app's diary: what the user pressed, which screen opened. The app writes these lines itself: with log() or plain console.log / warn / error (an object shows as short text; the browser's console gets it too). The simulator adds its own too: back, background, close, reload, theme, volume, vibration, link, ads, language, finger / mouse, and each touch (⚙ → Touches in console). The last 5000 lines are kept. Where it sits and how big: the “Buttons” tab → Console panel.
Vibration When the app vibrates (navigator.vibrate, Capacitor's Haptics), a zigzag lights up on each side of the phone for every buzz of the pattern; the console writes the pattern in ms. A buzz shorter than 80 ms still shows for 80 ms. Before the first touch on the screen the call is blocked, as in Chrome on a phone (the console warns).
Links On a phone a link to another address (not a page of the app itself) does not open inside the app: Capacitor hands it to Android, the app it belongs to opens, and ours goes to the background. The simulator does the same: that app (browser, Play Store, mail, phone, messages, maps) and the address appear on the screen, and the console writes the link. ◁ brings the app back. A button also opens a web address on your PC. Another app's own link (e.g. whatsapp:) opens on a phone only if that app is installed; otherwise nothing happens: the app stays and the console warns. Caught: a tapped link (also with target="_blank"), location.href and window.open.
Ads If the app uses AdMob, the simulator draws a stand-in ad instead of a real one. The banner lies over the app (at the top under the status bar, at the bottom above the navigation bar) and does not make it smaller: making room is the app's job. The interstitial covers the whole screen; ✕ or ◁ closes it. While it shows, ◁ does not reach the app and the app does not stop. A tap on an ad = a link to the Play Store: the app goes to the background, ◁ brings it back. The console writes every step. Close, ↻ and opening another app clear the ads.
Red line An error (an uncaught Promise too). Something in the app broke, even if the screen looks fine.
Filter Small chips under the console head: App, Simulator (its own lines), Touches, Commands, Warnings (yellow), Errors (red); touches and commands have their own colour in the console. Only the chips that are on show: click = hide, double click = only this (again = all). +N = the hidden ones, bring one back from the list. How many lines = in the chip's hint. Remembered.
Search The icon opens a field: only the lines that contain this text show (together with the filter). Esc clears the field; another click on the icon closes it.
⋮ More Copy = the lines that show now (filter and search) to the clipboard. Save as .txt = the same as a file (console-date-time.txt). Clear = the console is emptied.
New lines Scrolled up, the console no longer jumps to the end, and “↓ N new lines” appears. Click it = back to the end.
Repeated lines The same line several times in a row is written once, with a count at its end: ×12. A loop no longer floods the console. The time is the first line's.
Groups Similar lines in a row (same kind, same text, only the numbers differ; for touches the element too) fold into one group from 3 lines on: ▸, the newest line's time, the line's pattern (# for each number) and how many lines. Press = open / fold. After the filter or the search the groups form again from the lines that show. Copy and save write every line on its own.
Command line A small editor at the bottom of the console. What you type runs as JavaScript inside the app: Enter = run, Shift+Enter = a new line (2 lines to start, grows to 6). The command (›) and the answer (←) have their own colour in the console, an error is red; in the filter: “Commands”. For example startLevel(10) or localStorage.length. ↑ on the first line / ↓ on the last = earlier commands (the last 50). The icon in the console head shows / hides it (remembered). It works when the app has sim-bridge.js and is opened from a file, from localhost, or from the simulator's own address.
Data The second tab beside the console: what the app saved in localStorage (records, settings). The pencil = change a value, the bin = delete one, Clear data = delete all (press twice), like Android's “Clear storage”: after ↻ Reload the app starts as on a first launch. The list updates by itself when the app saves something. The simulator's own settings are not shown and not deleted.
abc Keyboard When you press a text field in the app, a keyboard comes up at the bottom of the screen and the app gets shorter, as on a phone: you see whether a field or a button gets covered. Its keys type into the field (⇧ = a capital, ↵ = Enter; ?123 is still a picture); the PC keyboard types too. ◁ or a press outside the field hides it. Its height: portrait as measured on a real phone (32 %, with a strip of icons on top), landscape an estimate.

6. Checks

Five checks, about ten minutes. Every time, before you show the app to anyone.

1 Different sizes Small (Old Android 360×640), typical (Galaxy A15), big (iPhone 16 Pro Max) and, if the app is for tablets too, iPad. Nothing is cut off, no text runs out of its box, every button can be reached. If the app works both upright and sideways, rotate on each size.
2 Bars and camera With the camera hole on, switch the bars: Gestures, 3 buttons, Hidden. Nothing important (a button, a score, a title) hides under a bar or the hole.
3 Back Press it on every screen. It goes where the user expects. The app never gets stuck and never quits by surprise.
4 Background and close Use the app for a moment, then Background → Return: it continues where it was (timer, music, game). Then Close → Open: is the progress still there? What is lost here is lost on a real phone too.
5 Console After all of the above, there are no red lines.

7. Limits

The simulator is close to a phone, but it is not a phone. Always try the app on a real phone before publishing.

Speed and sound A computer is faster than most phones.
Vibration strength The zigzags show how long and in what rhythm the phone buzzes, not how strongly.
A link's app On a phone an https link sometimes opens the site's own app instead of the browser (YouTube and others), if it is installed; the simulator always shows the browser. In Firefox only a tapped link is caught, not location.href.
Other websites Most big sites (Google, YouTube, GitHub, Facebook and others) forbid being shown inside another page, so the phone shows “… refused to connect” (in your browser's language). That is the site's own rule, the browser keeps it, and the simulator cannot get around it. Sites that allow it open: try the links under the Open app field. Your own app is not affected. A site that opens has no sim-bridge.js, so it only shows: the console, Back, finger mode and the simulator's other functions do not reach it.
Touch is approximate One finger, or two fingers pinching in or out. Not there: long-press, fling (a list stops the moment the finger lifts), two fingers moving freely. Drop-down lists, sliders and text selection need Mouse mode.
Fonts A phone may use a different font, so text can come out wider or narrower.
Bar and camera sizes Measured on one phone (Pixel 6 Pro); other phones differ by a few px.
Turned to the right Rotate gives sideways = the phone turned to the left (camera on the left). Turned to the right (camera on the right) and upside down (tablets only): only in Table mode (), when you turn the phone by hand. An iPhone has no upside down.
Timers in the background In the background the simulator does not stop the app's timers and sounds. The app has to stop them itself (a real phone does not always do it either).
Bar colour Not shown.
Volume steps Close to a phone's, not exact. Your computer's speakers are not a phone's speaker.
Ads A stand-in only: a real ad, its content and its loading time do not show (here 0.8 s). Banner and interstitial only; no rewarded, app-open or native ads. The consent form (EEA) does not show: the answer is the one a user outside the EEA gets. The adaptive banner's height is an estimate. On a phone the app may stop under an interstitial; here it does not.
On a phone The full version works on a computer only. On a phone (or a tablet) the simulator opens, but screenshot, video and Choose folder do not work. In a narrow window the top bar swipes sideways and the console is a strip at the bottom.
Screenshot and video Chrome and Edge only: Firefox and Safari cannot capture a browser tab. In Table mode a tilted phone (not at a right angle) allows the whole window only.
As its own app Installing and the web+phonesim: link: Chrome and Edge only, on the simulator opened as a web page. VS Code cannot hand over a folder as it is: the app needs a server (e.g. Live Server), or Choose folder by hand.
APK Only the web part runs. Native plugins (camera, files, notifications and others) are not here, only the simulator's stand-ins: ads, vibration, exit. Cordova's native calls get no answer (the console names each once), so an older app may stop where it works on a phone.

8. For app builders

This tab is for the people who make the app.

sim-bridge.js One line in the app's <head>. Without it the app still shows, but back, background, volume, finger mode, vibration, links, ads, the bars' sizes, the console and themes do not reach it, and the console says the app did not answer. app.html (the empty starter app) and the demo (demo/) already have it.
Safe on a phone Outside the simulator the bridge does nothing, so the same file becomes an Android app unchanged.
Ads in code The AdMob plugin: @capacitor-community/admob. The app gets it with one line: var AdMob = window.Capacitor && Capacitor.isNativePlatform() ? Capacitor.Plugins.AdMob : window.simAdMob; On a phone the real plugin answers; in the simulator the bridge's stand-in does, with the same calls and events (showBanner, hideBanner, resumeBanner, removeBanner, prepareInterstitial, showInterstitial, addListener). Example: the demo's ads.js.
As its own app In Chrome and Edge the simulator installs as its own app (Phone Sim): the install icon at the right of the address bar, or Chrome's ⋮ menu. It opens in its own window, has an icon in the Start menu and works offline too (after it was opened online once). Works on the simulator opened as a web page (the live demo or a local server), not from a file. For a project copy to install, copy manifest.webmanifest and the icons/ folder too.
From another program The installed app opens a link web+phonesim: + the app's address, e.g. web+phonesim:http://localhost:5500/. Any program that opens such a link (VS Code, a terminal) shows the app in the simulator window; an open window is reused, the same app loads afresh. The first time Chrome may ask whether to open Phone Sim. A ready VS Code task: README.md. The simulator from the web and the app on this computer (localhost): Chrome asks for permission once, under the address bar; until you allow it the phone stays white (after 4 s the console reminds you).
In your own project Copy this folder. In the project's sim.html change only the lines at the top: KEY = the project's name, APP = the app's main file and, if you like, DEFAULT_THEME = the theme on first start. Change nothing else in the copy. To update, copy the new sim.html + sim-bridge.js + sim-sw.js + lang/ over it and set those lines again.
