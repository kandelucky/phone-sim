Phone simulator: user guide

A phone on your computer screen, for trying out an app before it becomes a real Android app. No installation, no internet needed.

1. Open it

Double-click sim.html. It opens in your browser (Chrome or Edge work best). On the left is a phone with the app inside it, and on the right is the console, a list of what the app is doing (it can also sit under the phone, or be hidden: see Console panel below).

The simulator speaks English and Georgian: switch it under Settings (the gear) → Language (the last row). On first start it follows your browser's language. This guide gives each label in Georgian too, for when it is set to Georgian. Hold the mouse over any button to see its name and a short hint. The Info button (ⓘ, next to the gear) opens this whole guide inside the simulator, in the language you picked.
As its own app (Phone Sim). When the simulator is a web page (the live demo or a local server), Chrome and Edge can install it: the install icon at the right of the address bar, or Chrome's ⋮ menu. It then opens in its own window, has an icon in the Start menu and works offline too (after it was opened online once). Other programs can open an app in it with a link like web+phonesim:http://localhost:5500/; see section 8.

2. The buttons at the top

Each button does what a real phone would do. The app reacts as it would on a phone. The bar has three parts: on the left Open app, then the phone and the app (Back, Background, Close; Mute, Finger; Screenshot, Video, Present), in the middle, right above the phone, Reload; on the right Rotate and Device, Zoom, Info and Settings.

ButtonWhat it does
Open app
აპის გახსნა		 The first button: which app opens in the phone. It opens a small panel; click outside it or press Esc to close it.
Choose folder… (საქაღალდის არჩევა…): pick the app's folder (with index.html, or www/ or dist/ inside) and the app opens from it. sim-bridge.js is added by itself, ↻ shows your edits, a page refresh forgets the folder. Choose APK… (APK-ის არჩევა…): pick an Android app file (.apk) and its web part opens (assets/public/: Capacitor, assets/www/: Cordova, Construct 2). A native app (Java / Kotlin, Unity, Flutter) does not open; the console says so. Both buttons work only when the simulator is opened as a web page (the live demo or a local server), in Chrome or Edge.
The field under it: type a path from sim.html (for example myapp/index.html), paste a file path from Windows (Shift + right-click the file → Copy as path) or an address (for example http://localhost:5173), then press Enter. Empty means the default app, or an empty phone if there is none. It goes into the address bar, so a refresh opens it again. A file path works only while the simulator itself is opened from a file. An app opened from the field needs sim-bridge.js, or it only shows in the frame.
At the bottom of the panel: Download the demo app, a zip to try it with. Unzip it, then choose its folder.
Back
უკან		 The phone's back button; ◁ on the phone (in 3-button mode) and a swipe in from the edge (in Gestures mode) do the same. What "back" means is up to the app: go to the previous screen, close a window, or nothing. It is greyed out while the app is in the background or closed.
Background
ფონზე		 As if the user pressed Home or switched to another app. The app is told it is hidden, and its animations stop. ○ on the phone (in 3-button mode) does the same. The button turns into a filled one, shown below.
Return
დაბრუნება		 Brings the app back from the background. It should continue where it was.
Close
გათიშვა		 As if the user swiped the app away from the recent-apps list, or the phone closed it to free memory. The app gets no warning. Anything it had not saved is lost. The button turns filled: Open (გახსნა) starts the app from scratch. Only saved data survives.
Rotate
დატრიალება		 Turns the phone between upright and sideways. The icon shows what will happen: the faint screen is how the phone is now, the solid one is how it will be after the press.
upright now, press to turn sideways
sideways now, press to stand it up
The simulator remembers the position next time.
Mute
ხმის გათიშვა		 Silences all the app's sound at once, like the phone's mute. The button turns filled while the sound is off; press it again (Unmute, ხმის ჩართვა) and the sound comes back at the same level. The number of waves on the icon shows the current level. The level itself is set in Settings.
Finger mode
თითის რეჟიმი		 On by default. Over the phone screen the mouse works as a finger, and the app gets real touches, as on a phone. The arrow disappears there; a faint ring shows where the finger would land.
• Press: a small white circle appears where the finger touches. Drag to slide the finger; a list scrolls under it.
• Mouse wheel: two fingers. Wheel up = they move apart (zoom in), wheel down = they come together (zoom out). They lift a moment after the wheel stops.
Outside the phone screen the mouse stays a normal mouse.
Mouse mode
მაუსის რეჟიმი		 Press the finger button to switch to this. The mouse is a plain mouse on the screen too. Use it for what a fake finger cannot do: a drop-down list, a slider, selecting text. Press again for the finger.
Reload
გადატვირთვა		 In the middle of the bar, right above the phone. Starts the app again. The console keeps its lines, so you can compare before and after.
Device
მოწყობილობა		 The list left of Zoom. Which phone or tablet to show, grouped by maker: Samsung (foldables too, folded / open), Pixel, iPhone, iPad, then generic sizes (an older small Android, a tall screen, a small tablet); newest first in each group. The first start shows Pixel 6 Pro, later the one you picked last. A real device shows in its own frame: its body, keys and camera hole, notch or Dynamic Island where they are on the real one. An iPhone or the iPad turns on iPhone mode: the iOS status bar, a home line at the bottom instead of ◁ ○ □ (swipe up from it = Home), the notch or the Dynamic Island, and the iOS safe areas. There is no system Back: the Back button sends nothing, and a swipe from the edge stays with the app. Settings → Bars and Camera are off in this mode. The sizes are Apple's published ones, not measured on a device. The numbers (for example 360×800) are the size the app "sees", not the camera megapixels or the screen's hardware pixels. Not in the list? Type your own size in Settings → Size.
PNG Screenshot
სქრინშოტი		 The camera icon opens a menu; each choice downloads a PNG file. Screen: the phone's screen only (with the system bars, without the camera and the rounded corners). The console writes the size and whether it fits Google Play's rule: each side 320–3840 px, the long side at most twice the short one. 360 × 800 is too long; Settings → Size 360 × 640 fits. Phone: the phone with its frame and camera, on a transparent background, no shadow. For about a second the background turns black, then white: the two frames give the file its transparency. Whole window: the simulator as you see it. The browser asks for permission every time: pick this tab. For the shot Chrome draws the tab twice as sharp, so the file is twice the size the phone shows at on your monitor; for more, raise the zoom (for Screen and Phone the whole phone must be in view). Works in Chrome and Edge.
Video
ვიდეო		 The phone as a video file. Press = a menu; a pick = recording starts: the browser asks for permission, pick this tab. While it records, the button is red and the time shows beside it. Press again = it stops and the file downloads; the browser's own “Stop sharing” stops and saves it too. Screen: the screen only (with the system bars and the touch circles, without the camera and the rounded corners). Phone: the phone with its frame and camera, no shadow, on the page's background (an MP4 cannot be transparent), touch circles included. While it records, Rotate, Device and Size are locked, Zoom is not. Both work in presentation mode too. Format: MP4 if the browser can write it, otherwise WEBM. Sound: ⚙ → Sound in video. The console writes the size, length, format and MB.
Presentation mode
პრეზენტაციის რეჟიმი		 The top bar, the console and the line under the phone hide; only the phone stays, in the middle of the window. It works as usual. A faint dot sits in the window's top-left corner: the mouse on it opens a card with three buttons, Video and Screenshot (the same menus as in the top bar) and Exit; 0.8 s after the mouse leaves, it folds back into the dot. On entering, the card shows for a few seconds. While a video records, the dot blinks red and the time shows beside it. The dot and the card do not show in a screenshot or a video. Esc exits too when the app does not have the focus (click outside the phone first). The zoom stays as it was. Not remembered: a refresh opens the normal view. Leaving it while a video started here records stops the recording and saves the file.
100% Zoom
მასშტაბი		 How big the phone is on your monitor. The button shows the current scale; a click opens its panel. Fit (ჩატევა) shrinks the phone to your window, never above 100%. The slider goes from 40 to 200% in steps of 10; 50% and 100% have buttons too. Natural (ნატურალური) = real size: the phone on the screen is as big as in your hand (a real device by its body's millimetres; a generic size or your own = Android's 160 dp per inch); the button then shows 1:1. For this the simulator must know the screen's density: the panel's bottom line → Calibrate (გასწორება): hold a bank card to the screen and match the outline (no card: a ruler, the outline is 85.6 × 54 mm). It is saved for each screen; on an unknown screen Natural opens Calibrate first. Windows scaling and the browser's Ctrl +/− do not spoil the size. When the phone is bigger than the window, scroll with the scrollbars, or with the wheel outside the phone screen (on the screen the wheel is two fingers). The app itself does not change.
Console panel
კონსოლის პანელი		 Where the console sits: Right (მარჯვნივ), upright beside the phone; Bottom (ქვემოთ), wide under the phone; or Hidden (დამალვა). The icon shows where it is now; a click opens the menu. Size: drag the panel's inner edge (width 260–900 px, height from 120 px to 60% of the window). A double click on the edge, or Default size (საწყისი ზომა) in the menu, gives 400 / 260 px back. The simulator remembers it.
Info
ინფორმაცია		 Next to the gear. Opens one window with this guide, in the simulator's language: tabs on the left (buttons, finger and zoom, settings, screen and console, checks, limits, for app builders). Close it with ✕, Esc or a click outside.
Settings
პარამეტრები		 On the right side of the bar. Opens the settings panel (next section).

While the app is in the background or closed, a cover sits on the phone screen and says how to bring the app back. Before any app is opened, the phone is empty and the cover points to Open app.

3. Settings

Click the gear to open the panel. Click anywhere outside it, or press Esc, to close it. Every choice is remembered.

SettingWhat it changes
Size
ზომა		 Type your own width × height if your phone is not in the Device list in the top bar.
Bars
ზოლები		 The phone's top bar (clock, battery) and its bottom bar:
• Gestures (ჟესტები): a thin line at the bottom, as on most new phones. In finger mode the swipes work: in from the left or right edge = Back (a round arrow shows at the edge; a short swipe does nothing), up from the bottom line = Home. The app no longer gets such a touch (it gets touchcancel), as on a phone;
• 3 buttons (3 ღილაკი), the default: ◁ ○ □ at the bottom. Many people still use them. ◁ = Back, ○ = Home (the app goes to the background), □ does nothing. When a phone (not a tablet) is sideways they move to the right edge;
• Hidden (გარეშე): no bars, as in a full-screen game.
Camera hole
კამერის ხვრელი		 The front camera's hole in the screen. On by default. Upright it is at the top; sideways it is on the left. It covers a strip of the screen even when the bars are hidden.
Theme
თემა		 Colour sets (light, dark and many more), for apps that use them. The app changes its colours at once.
Volume
ხმა		 The phone's volume buttons: a slider from 0 to 15, as on Android. It makes all the app's sound (music and effects) louder or quieter, and the phone shows its volume bar for a moment. The app is not told about it, just as on a real phone. Moving the slider also turns mute off.
Ads
რეკლამა		 For an app with AdMob ads (see section 8). Ads come: the app gets a stand-in ad. No ads: every ad fails to load (“No fill”), as with no internet or nothing to show. Use it to check that the app still works without ads.
Touches in console
შეხებები კონსოლში		 On by default. In finger mode every gesture becomes one console line: tap x, y, double tap, swipe (the arrow = the way the finger moved, the distance, the time), scroll (the browser scrolled by itself), two fingers apart or together (×), a gesture from the edge or the bottom (in Gestures mode). At the end: the element the finger landed on. In the filter: Touches.
Internet
ინტერნეტი		 Off = as if the phone had no internet. The app's own files still load (in an APK they are on the phone), but a request to another address (fetch, XMLHttpRequest) fails, navigator.onLine is false, the app gets the offline / online event, and no ads come. The signal and Wi-Fi icons in the status bar fade. Pictures and scripts loaded by an HTML tag are not stopped.
Font size
შრიფტის ზომა		 Android's “Font size” setting. On a phone the WebView makes text bigger with it while the boxes stay the same, so text may no longer fit. 130% and 200% show where the layout breaks. Text drawn on a canvas does not change. An estimate: a line height given in px does not grow.
FPS meter
FPS მთვლელი		 A number in the corner of the screen: how many frames a second the app draws, and the longest frame of the last half second (ms). Green = 55+, yellow = 30+, red = fewer. A PC is faster than a phone: what stutters here is worse on a phone.
Sound in video
ხმა ვიდეოში		 On by default. A video records the app's sound too (music, effects), at the ⚙ → Volume level. In the browser's question, sharing the tab's sound must be on; if it is not, the video records without sound and the console says so.
Language The simulator's own words: English or Georgian. One choice for all projects. The app inside the phone does not change.

4. The line under the phone

It tells you what the app gets right now. For example:

Galaxy A15, typical · 360 × 800 · app 360 × 800 · under the bars: ↑28 ↓22 ←0 →0 · 75%
  • 360 × 800: the screen size.
  • app 360 × 800 (აპი): the space the app draws on.
  • under the bars ↑28 ↓22 ←0 →0 (ზოლების ქვეშ): how much of each edge (top, bottom, left, right) is covered by a bar or the camera hole. The app must keep its buttons and text out of those strips. If this part is missing, the app is set up so the bars never cover it; then the app space is simply smaller.
  • 75%: how big the phone is shown: shrunk to fit your window, the zoom you picked, or Natural. It does not affect the app.

5. The console

The console is the app's diary: what the user pressed, which screen opened, what was calculated. The app writes these lines itself (with log(), or plain console.log / warn / error), so how much you see depends on the app. The last 5000 lines are kept.

  • Red lines are errors (an uncaught Promise too). Something in the app broke, even if the screen looks fine.
  • The simulator adds its own lines too: Back, Home, Background, Close, Reload, theme, volume, vibration, link, ads, language, finger or mouse mode, and each touch (Settings → Touches in console).
  • Vibration (ვიბრაცია): when the app vibrates (navigator.vibrate, Capacitor's Haptics), a zigzag lights up on each side of the phone for every buzz of the pattern, and the console writes the pattern in ms. A buzz shorter than 80 ms still shows for 80 ms. Before the first touch on the screen the call is blocked, as in Chrome on a phone (the console warns).
  • Links (ბმულები): on a phone a link to another address (not a page of the app itself) does not open inside the app: Capacitor hands it to Android, the app it belongs to opens, and ours goes to the background. The simulator does the same: that app (browser, Play Store, mail, phone, messages, maps) and the address appear on the screen, and the console writes the link. ◁ brings the app back. A button also opens a web address on your PC. Another app's own link (e.g. whatsapp:) opens on a phone only if that app is installed; otherwise nothing happens: the app stays and the console warns. Caught: a tapped link (also with target="_blank"), location.href and window.open.
  • Ads (რეკლამა): if the app uses AdMob, the simulator draws a stand-in ad instead of a real one. The banner lies over the app (at the top under the status bar, or at the bottom above the navigation bar) and does not make it smaller: the app has to make room for it. The full-screen ad (interstitial) covers the screen; ✕ or ◁ closes it. While it shows, ◁ does not reach the app, and the app does not stop by itself. A tap on an ad is a link to the Play Store: the app goes to the background, ◁ brings it back. The console writes every step. Close, Reload and opening another app clear the ads.
  • Filter (ფილტრი): small chips under the console head: App, Simulator (its own lines), Touches, Commands, Warnings (yellow), Errors (red). Touches and commands have their own colour in the console. Only the chips that are on show: click = hide, double click = only this (again = all). +N = the hidden ones: bring one back from the list. How many lines = in the chip's hint. The simulator remembers your choice.
  • Search (ძებნა): the magnifier opens a field; only the lines that contain the text show (together with the filter). Esc clears it, another click on the magnifier closes it.
  • ⋮ More (მეტი): Copy puts the lines that show now on the clipboard, Save as .txt saves them as a file (console-date-time.txt), Clear empties the console.
  • New lines: scrolled up to read, the console no longer jumps to the end; “↓ N new lines” appears, and a click on it goes back to the end.
  • Repeated lines: the same line several times in a row is written once, with a count at its end (×12), so a loop does not flood the console. The time is the first line's.
  • Groups (ჯგუფები): similar lines in a row (same kind, same text, only the numbers differ; for touches the element too) fold into one group from 3 lines on: ▸, the newest line's time, the line's pattern (# for each number) and how many lines. Click = open / fold. After the filter or the search the groups form again from the lines that show. Copy and save write every line on its own.
  • Command line (ბრძანების ხაზი): a small editor at the bottom of the console. What you type runs as JavaScript inside the app: Enter = run, Shift+Enter = a new line (2 lines to start, it grows to 6). The command (›) and the answer (←) have their own colour, an error is red; in the filter: Commands. For example startLevel(10) or localStorage.length. ↑ on the first line / ↓ on the last bring back earlier commands (the last 50). The icon in the console head shows or hides it (remembered). It works when the app has sim-bridge.js and is opened from a file, from localhost, or from the simulator's own address.
  • Data (მონაცემები): the second tab beside the console shows what the app saved in localStorage (records, settings). The pencil changes a value, the bin deletes one, Clear data deletes all (press twice), like Android's “Clear storage”: after Reload the app starts as on a first launch. The list updates by itself when the app saves something. The simulator's own settings are not shown and not deleted.
  • Keyboard (კლავიატურა): when you press a text field in the app, a keyboard comes up at the bottom of the screen and the app gets shorter, as on a phone, so you see whether a field or a button gets covered. Its keys type into the field (⇧ = a capital, ↵ = Enter; ?123 is still a picture); the PC keyboard types too. ◁ or a press outside the field hides it. Its height: portrait as measured on a real phone (32 %, with a strip of icons on top), landscape an estimate.

6. Before you show the app to anyone

Five checks, about ten minutes. Do them every time before you hand the app over.

  1. Different sizes. Open the app on a small phone (ძველი Android 360×640), a typical one (Galaxy A15), a big one (iPhone 16 Pro Max) and, if the app is for tablets too, an iPad. Nothing is cut off, no text runs out of its box, every button can be reached. If the app works both upright and sideways, rotate on each size.
  2. Bars and the camera hole. With the camera hole on, switch Bars between Gestures, 3 buttons and Hidden. Nothing important (a button, a score, a title) hides under a bar or the hole. The numbers under the phone show how much each edge loses.
  3. Back. Press Back on every screen. It goes where a user would expect. The app never gets stuck and never quits by surprise.
  4. Background and close. Use the app for a moment, then Background → Return: it continues where it was (timer, music, game). Then Close → Open: is the progress still there? What is lost here is lost on a real phone too.
  5. Console. After all of the above, there are no red lines.

7. What the simulator cannot show

It is close to a phone, not a phone. Always try the app on a real phone before publishing.

  • Speed and sound: a computer is faster than most phones.
  • Vibration strength: the zigzags show how long and in what rhythm the phone buzzes, not how strongly.
  • A link's app: on a phone an https link sometimes opens the site's own app instead of the browser (YouTube and others), if it is installed; the simulator always shows the browser. In Firefox only a tapped link is caught, not location.href.
  • Touch is close, not exact: one finger or a two-finger pinch. No long-press, no fling (a list stops the moment the finger lifts), no two fingers moving freely. Drop-down lists, sliders and text selection need Mouse mode.
  • Fonts: a phone may use a different font than your computer, so text can be wider or narrower.
  • Bar and camera sizes were measured on one phone (Pixel 6 Pro); other phones differ by a few px.
  • Sideways means the phone turned to the left (camera on the left). Turned to the right is not shown.
  • Background does not stop the app's timers or sounds. The app has to stop them itself (a real phone does not always do it either).
  • The colour of the bars is not shown.
  • Volume steps are close to a phone's, not exact, and your computer's speakers are not a phone's speaker.
  • Ads are stand-ins: no real ad, its content or its loading time (here 0.8 s). Banner and full-screen ads only; no rewarded, app-open or native ads. The consent form (EEA) does not show: the app gets the answer a user outside the EEA gets. The height of an adaptive banner is an estimate. On a phone the app may stop under a full-screen ad; in the simulator it does not.
  • Screenshot and video work in Chrome and Edge only: Firefox and Safari cannot capture a browser tab.
  • Installing it as an app and the web+phonesim: link: Chrome and Edge only, on the simulator opened as a web page. VS Code cannot hand over a folder as it is: the app needs a server (e.g. Live Server), or Choose folder by hand.
  • An APK: only its web part runs. Native plugins (camera, files, notifications and others) are not there, only the simulator's stand-ins: ads, vibration, exit. Cordova's native calls get no answer (the console names each once), so an older app may stop where it works on a phone.

8. For people building apps

  • The app must include sim-bridge.js (one line in its <head>). Without it the app still shows, but Back, Background, volume, finger mode, vibration, links, ads, the bars' sizes, the console and themes do not reach it, and the console says the app did not answer. app.html (the empty starter app) and the demo in demo/ already have it.
  • The bridge does nothing outside the simulator, so the same app file can become a real Android app unchanged.
  • Ads: the app uses the AdMob plugin for Capacitor (@capacitor-community/admob) and gets it with one line: var AdMob = window.Capacitor && Capacitor.isNativePlatform() ? Capacitor.Plugins.AdMob : window.simAdMob; On a phone the real plugin answers; in the simulator the bridge's stand-in does, with the same calls and events. The demo's ads.js shows it.
  • From another program: the installed app (Phone Sim, section 1) opens a link web+phonesim: + the app's address, e.g. web+phonesim:http://localhost:5500/ (5500 = VS Code's Live Server). Any program that opens such a link shows the app in the simulator window; an open window is reused, the same app loads afresh. A ready VS Code task: README.md. The simulator from the web with an app on this computer: Chrome asks for permission once, under the address bar; until you allow it the phone stays white (after 4 s the console reminds you).
  • Technical details (how the app answers Back, saves on Background, keeps clear of the bars): README.md in the same folder.
Using the simulator in your own project
  1. Copy everything in this folder into the project.
  2. In the project's sim.html, change only the lines at the top of the script: KEY = the project's name (so two projects do not mix up their settings), APP = the app's main file (empty in this folder, so the phone starts empty; for a new app usually app.html) and, if you like, DEFAULT_THEME = the theme on first start.
  3. Never change the copy in any other way. To update, copy the new sim.html, sim-bridge.js and sim-sw.js into the project again and set the same lines. This way every project gets the same, latest simulator.
